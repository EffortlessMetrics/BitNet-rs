security) and now overlap heavily. Goal is to extract every useful patch,
test, and review finding into mergeable canonical work against current
`main`, then close duplicates with absorption notes — never close before
harvesting.

## Process for each cluster

1. Read every diff in the cluster (not just the title/body).
2. Extract useful elements — implementation choices, edge cases, tests,
   review findings, benchmark setup.
3. Synthesize one canonical patch on the consolidation branch against
   current `main`, with at least the validation gate the cluster needs.
4. Land the canonical patch.
5. Close the consumed PRs with an absorption comment that lists what was
   carried over.

A PR is closed only if one of the following holds: merged directly,
merged indirectly via absorption, rejected with a reason, or already
present in `main`.

## Closure-comment templates

**Absorbed:**
> Closing as absorbed into <commit-or-PR>. Reviewed this PR and carried
> over: <bullet list of what landed>. The merged candidate adds
> current-`main` validation. Reopen with a focused follow-up if there is
> a distinct improvement here that wasn't captured.

**Stale/superseded:**
> Closing as superseded by <commit-or-PR>, which consolidates this
> change against current `main` with tests. This PR appears to be one of
> several automated duplicates for the same idea.

**Obsolete:**
> Closing as obsolete. Current `main` already contains this fix or an
> equivalent implementation. Verified at <file:function>.

**Rejected (semantics):**
> Closing after review. The change is labelled performance but alters
> observable sampling/repetition behavior without enough equivalence
> coverage. The allocation/perf idea is retained in <PR> with narrower
> tests.
