# API Snapshots

This directory stores committed API contracts and generated baselines that are
used for review, compatibility checks, and release audits. Most files here are
snapshots, not hand-written guides.

## Contents

| Path | Purpose |
|------|---------|
| `cli/help.txt` | Baseline top-level `bitnet-cli --help` output. |
| `cli/subcommands.json` | Machine-readable CLI command inventory. |
| `ffi/bitnet_ffi.h` | C FFI header generated by `cbindgen`. |
| `ffi/cbindgen.toml` | Configuration for the generated FFI header snapshot. |
| `ffi/ffi.symbols.txt` | Baseline exported FFI symbol inventory. |
| `rust/*.public-api.txt` | `cargo public-api` baselines for selected crates. |
| `v1/inference.json` | JSON schema for the v1 inference API contract. |

## Regeneration

The public API diff workflow is defined in
`.github/workflows/contracts.yml`. It computes `cargo public-api` diffs for
workspace library crates and uploads review artifacts.

The Phase 1 maintenance workflow is defined in
`.github/workflows/phase1-maintenance.yml`. It regenerates deterministic
maintenance artifacts and watches `docs/api/rust/**` for baseline changes.

When updating a baseline manually, keep the generated-file warning intact and
run the narrow command for the affected artifact. The Rust API snapshots record
their expected command in the file header, for example:

```sh
cargo public-api -p bitnet-ffi > docs/api/rust/bitnet-ffi.public-api.txt
```

The FFI header is generated from the `docs/api/ffi/cbindgen.toml`
configuration, and the checked-in header starts with the cbindgen generated-file
warning.
